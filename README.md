# ProNoobs Tournament API

Express and PostgreSQL API for managing Dota 2 tournaments, teams, player identities and MMR, rosters, and registrations. It is designed to be shared by the website and a future Discord bot.

## Requirements and setup

- Node.js 20 or later
- PostgreSQL

From this directory, create the database and apply the schema:

```bash
createdb pronoobs
psql -d pronoobs -f migrations/001_initial_schema.sql
psql -d pronoobs -f migrations/002_team_signup_fields.sql
pnpm install
```

Copy `.env.example` to `.env`. Set `DATABASE_URL`, create a long random `ADMIN_API_KEY`, and configure `CORS_ORIGINS` with the website's full origin(s), comma-separated. Start the API with `pnpm dev` for development or `pnpm start` for production. It listens on port 3000 by default.

`GET /health` checks the API and database connection.

## Routes

Public read routes:

- `GET /api/tournaments` and `GET /api/tournaments/:id`
- `GET /api/teams` and `GET /api/teams/:id` (include team name, captain's Discord name, agreement acceptance, and five roster members with MMR)
- `GET /api/tournaments/:id/registrations`

All write routes require `X-API-Key: <ADMIN_API_KEY>`:

- `POST /api/tournaments` — create a tournament. Use status `registration_open` to accept entries.
- `PATCH /api/tournaments/:id` — update tournament details, dates, team limit, or status.
- `POST /api/teams` — create a team with `name`, `captainDiscordName`, `captainAgreementAccepted: true`, and exactly five members. Each member needs a `displayName` (the Steam/Dota name) and non-negative integer `mmr`. Optional fields: `discordId`, `steamId`, `position`, and `isCaptain`. The first member is always the captain.
- `PATCH /api/players/:id` — update a player's display name, MMR, Discord ID, or Steam ID.
- `POST /api/tournaments/:id/registrations` with `{ "teamId": 1 }` — register an existing team while registration is open and capacity remains.
- `PATCH /api/registrations/:id` with `{ "status": "approved" }` — set registration status to `pending`, `approved`, `rejected`, or `withdrawn`.

Keep the API key on a trusted server or bot. Do not place it in browser code. Direct website writes need user authentication or a server-side form handler first.

## Data model

The first migration creates tournaments, teams, players, team memberships, and tournament registrations. The second adds the captain's Discord name and agreement acceptance timestamp/version. Agreement timestamps are generated by the API and use version `pronoobs-captain-agreement-v1`. Public team responses return names and MMR but omit player Discord and Steam IDs. Those IDs remain optional and unique in storage. A player can belong to one team roster at a time; each team can have one captain. Registration capacity is checked transactionally.

The captain agreement covers responsibility for the team's participation and organization, best efforts to follow tournament rules including the fair-play MMR cap and a non-toxic environment, and communication with organizers about questions or changes.

Example team payload:

```json
{
  "name": "Ancient Stack",
  "captainDiscordName": "farid#1234",
  "captainAgreementAccepted": true,
  "members": [
    { "displayName": "PlayerOne", "mmr": 4200, "isCaptain": true },
    { "displayName": "PlayerTwo", "mmr": 3500 },
    { "displayName": "PlayerThree", "mmr": 2800 },
    { "displayName": "PlayerFour", "mmr": 3100 },
    { "displayName": "PlayerFive", "mmr": 2500 }
  ]
}
```
